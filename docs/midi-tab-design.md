# MIDI → ベース/ギター 楽譜・タブ譜アプリ 設計書

MIDIファイルを読み込み、ベース／ギター用の**五線譜**と**タブ譜（TAB）**を生成・表示・書き出しするWebアプリ。

## 0. 方針

- **サーバー不要のクライアントサイド（ブラウザ完結）アプリ**にする。
  - 既存の静的サイト（GitHub Pages）にそのまま追加でき、公開が容易。
  - MIDIファイルがブラウザ外に出ない（プライバシー面で有利）。
  - 運用コスト・スケール・障害の心配がない。
- 既存サイトに合わせ **ビルドツールなし**。ライブラリは ESM CDN から `import`。
  - 将来は `assets/vendor/` へ同梱（vendoring）に切り替え可能。

## 1. データフロー

```
MIDIファイル (.mid)
  │  midiLoader
  ▼
Midiオブジェクト（トラック・音符・PPQ・拍子・テンポ）
  │  trackAnalyzer  … パート自動判定＋手動選択
  ▼
対象トラックの音符列
  │  noteModel      … 拍空間でクオンタイズ → 小節/休符/音価へ
  ▼                    （tabMapper で音高→弦・フレット割当）
表示モデル（measures[] / clef / tuning / timeSig …）
  │  renderer (VexFlow)
  ▼
五線譜 + タブ譜（SVG）  ──▶ exporter … PNG / 印刷
```

## 2. クオンタイズの考え方（重要）

生MIDIの発音タイミングは人間の演奏由来で微妙にズレている。そのまま音価にすると読めない楽譜になるため**記譜前にクオンタイズが必須**。ただし処理は2系統に分かれ、必要度が違う。

| 処理 | クオンタイズ | 理由 |
|---|---|---|
| 五線譜のリズム/音価 (`noteModel`) | **必須** | タイミングを丸めないと記譜できない |
| タブ譜の弦・フレット割当 (`tabMapper`) | **不要** | 音高(pitch)は正確な整数。タイミングのズレは無関係 |

掛け方のポイント:

- **拍（tick）空間で丸める**。秒でやるとテンポ変化で崩れる。
- **開始(onset)と長さ(duration)の両方**を丸める。
- **グリッドは設定可能**（既定1/16、必要に応じ1/8）。
- **元データは壊さない**。生の音符列は保持し、クオンタイズは表示用の派生レイヤーとして再計算可能にする。

内部表現は**16分音符単位（sixteenths）**に正規化して扱い、グリッド（`gridDiv`）はスナップの粗さだけを決める。

## 3. モジュール構成

```
midi-tab.html                 画面（UI）
assets/midi-tab/
├─ app.js                     エントリ。DOM制御・状態管理・各モジュール結線
├─ midiLoader.js              File → ArrayBuffer → @tonejs/midi でパース
├─ trackAnalyzer.js           トラック要約・パート自動判定・選択
├─ noteModel.js               クオンタイズ → 小節/休符/音価 → 表示モデル生成
├─ tabMapper.js               チューニング定義・音高→(弦,フレット)割当

```

## 5. アルゴリズム詳細

### 5.1 パート判定 (`trackAnalyzer`)

- GM音色番号で判定: ベース `32–39` / ギター `24–31`。`instrument.family` も参照。
- 判定できない場合は平均音高で推定（低ければベース）。
- **自動判定は外れることがある**ため、手動でトラックを選び直せるUIを必須とする。

### 5.2 記譜モデル (`noteModel`)

1. `sixteenth = ppq/4`、`snap = ppq*4/gridDiv`、`f = 16/gridDiv`。
2. 各音符を snap グリッドへスナップし、16分単位へ換算（`start`, `len`）。
3. 同時刻開始をグループ化（和音）。重なりは後発の開始でクランプし**単声タイムライン**化。
4. 音符間の空きに**休符**を挿入し、末尾は小節末まで休符で充填。
5. 小節境界（`measureSix = num*16/den`）でトークンを分割。
6. 各トークン長を音価へ**分解**（`[16,12,8,6,4,3,2,1]` の貪欲和）。
   - `12→付点2分, 6→付点4分, 3→付点8分` 等。

### 5.3 弦・フレット割当 (`tabMapper`)

チューニング（開放弦のMIDI番号、低→高）:

```js
bass4:  [28, 33, 38, 43]            // E1 A1 D2 G2
bass5:  [23, 28, 33, 38, 43]        // B0 追加
guitar: [40, 45, 50, 55, 59, 64]    // E2 A2 D3 G3 B3 E4
```

- 各音高について候補 `fret = pitch - openString`（`0..maxFret`）を列挙。
- **MVP=貪欲法**: `cost = |fret - prevFret| + fret*0.15` を最小化（低フレット＋手の移動最小）。
- VexFlow弦番号は「1=最上段=最高音弦」。配列index(低音側=0)に対し `str = 弦数 - index`。
- **Phase 2 で DP(Viterbi)** に置換し、音列全体の総移動コストを最小化。

### 5.4 描画 (`renderer`)

- 小節ごとに上段 `Stave`＋下段 `TabStave` を配置し、同一トークン列から
  五線譜音符(`StaveNote`)とタブ音符(`TabNote`)を生成、**同じ Formatter で整列**。
- 休符はタブ側を `GhostNote`（不可視スペーサ）で埋め、拍位置を揃える。
- 声部は `Voice.Mode.SOFT`（厳密な小節長チェックを無効化）で堅牢化。
- 複数小節は行折り返し（`measuresPerRow`）。

## 6. UI

- ファイルのドロップ／選択
- トラック（パート）選択、楽器（bass4 / bass5 / guitar）
- クオンタイズグリッド（1/8, 1/16）、1行あたり小節数
- 書き出し: PNG / 印刷

## 7. 既知の割り切り（MVPの限界）と今後

MVPで割り切っている点（意図的）:

- **単声中心**。同時発音は和音として最高len基準にまとめる簡易処理。
- 小節をまたぐ音符・分解した音価は**タイ記号なしで再発音表示**（リズムは保つが再アーティキュレーション扱い）。
- 三連符・複合拍子の自動判定はしない（固定グリッド）。
- 可読性のため五線譜は**オクターブ上げ表示（8vb 相当）**。タブ譜のフレットは実音ベース。
- 運指は貪欲法（局所最適）。

フェーズ計画:

| フェーズ | 内容 |
|---|---|
| **MVP** | MIDI読込→トラック選択→五線譜＋タブ表示（1/16量子化, 貪欲運指, PNG出力） |
| Phase 2 | DP運指最適化 / タイ・連桁 / チューニング&カポ拡張 / PDF出力 |
| Phase 3 | 再生(Tone.js) / MusicXML書き出し / 三連符など記譜精度向上 |

## 8. Web公開

静的ファイルのみのため公開は容易。

- **GitHub Pages（既存サイトと同方式・推奨）**: リポジトリに `midi-tab.html` と
  `assets/midi-tab/` を追加してプッシュ → Settings → Pages で公開ブランチ指定 →
  `https://<user>.github.io/funny-jpop_world/midi-tab.html` で公開。HTTPS/独自ドメイン無料。
- 代替: Netlify / Vercel / Cloudflare Pages（フォルダをドラッグ&ドロップ or Git連携）。
- サーバー・DB不要。CDNからライブラリを読むだけ（将来は同梱に切替可）。
